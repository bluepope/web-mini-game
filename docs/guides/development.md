# Pond Party · 우리들의 작은 연못

ASP.NET Core SignalR와 TypeScript/Canvas로 만든 2~8인 턴제 웹게임입니다. 플레이어마다 개구리 하나를 조종합니다. 자동으로 좌우 왕복하는 화살표를 보고 **점프 버튼 하나**만 누르세요. 빈 연꽃잎에 착지하면 성공, 물이나 다른 개구리로 향하면 실패입니다.

## 실행

필요 환경: .NET 10 SDK, Node.js 22.12 이상(현재 검증 환경: Node 24).

프로젝트 루트의 터미널에서 서버를 실행합니다.

```powershell
dotnet run --project backend --no-launch-profile --urls http://127.0.0.1:5072
```

다른 터미널에서 프론트엔드를 실행합니다.

```powershell
cd frontend
npm install
npm run dev
```

브라우저에서 http://localhost:5173 을 여세요. 이름을 입력하고 연못을 만든 뒤 **초대 링크 복사**를 눌러 친구에게 보냅니다. 친구가 링크를 열면 해당 연못이 자동으로 선택되며, 이름을 입력하고 참가하기를 누르면 됩니다. 첫 화면에 링크를 직접 붙여 넣어도 참가할 수 있습니다. 참가자가 준비 완료를 누르면 방장이 경기를 시작할 수 있습니다.

초대 링크 예시: http://localhost:5173/?room=ABC123. 현재 접속한 주소를 기준으로 만들므로 휴대폰 등 다른 기기에 공유할 때는 개발 PC의 LAN IP 주소로 접속한 뒤 링크를 복사하세요. localhost/127.0.0.1은 같은 PC에서 테스트할 때 사용합니다. 서버 재시작이나 방 정리 후에는 새 링크가 필요합니다. 다른 방에 이미 참가 중인 탭에서는 그 방을 나온 후 초대된 연못에 참가합니다.

- 최소 2명, 최대 8명. 한 라운드에 모두 한 번씩 점프합니다.
- 마지막 참가자의 점프 결과(또는 시간 초과)가 확정되면 다음 라운드가 시작됩니다. 같은 라운드의 참가자들은 같은 조준 속도를 사용하며, 다음 라운드마다 직전 속도의 1.1배로 빨라집니다. 1라운드 1배 → 2라운드 1.1배 → 3라운드 1.21배입니다. 왕복 주기는 `4400ms / 1.1^(라운드-1)`이며 새 경기는 기본 속도로 시작합니다. 연습모드는 시도 횟수와 무관하게 기본 속도를 유지합니다.
- 점프 경로가 다른 개구리에 닿지 않고, 착지점이 빈 연꽃잎 중심에서 반지름의 82% 안에 있으면 성공입니다. 성공 범위는 게임판에도 점선으로 보입니다. 성공 범위 확대는 방향별로 동일하게 적용되며 충돌 판정에는 영향을 주지 않습니다.
- 1·3·5라운드를 선택할 수 있고 서버는 1~10라운드를 지원합니다.
- 화살표 방향은 자동입니다. 클릭/터치/스페이스만 사용합니다.
- 각 턴은 10초입니다. 성공하면 출발한 자리가 새 빈자리가 됩니다.
- 실패하거나 시간이 지나면 실패를 기록하고 원래 자리를 유지합니다.
- 모든 라운드가 끝나면 성공 횟수로 순위를 정합니다. 동점은 공동 우승입니다.
- 새로고침과 일시적 연결 끊김은 같은 참가자로 복구합니다. 탭별 sessionStorage를 사용합니다.
- 같은 참가자 세션을 다른 탭에서 복제하면 가장 최근 연결만 조작할 수 있습니다. 별도 참가자는 새 탭에서 이름을 입력하세요.
- 휴대폰은 같은 네트워크에서 개발 PC의 IP와 5173 포트로 접속합니다. 방화벽에서 허용된 환경이어야 합니다. 개발 프록시가 SignalR 연결도 전달합니다.

## 혼자 연습하기와 음악

첫 화면에서 **혼자 연습하기**를 누르면 방 코드나 다른 참가자 없이 바로 시작합니다. 이름은 생략할 수 있습니다. 나와 움직이지 않는 연습 개구리 3마리, 연꽃잎 5개로 구성되며 점프 속도와 판정은 멀티플레이와 같습니다. 성공·실패·시간 초과 후 다시 내 차례가 돌아오고 시도 횟수, 성공 횟수, 성공률을 표시합니다. 횟수 제한 없이 연습하며 **연습 끝내기**로 언제든 돌아갈 수 있습니다. 새로고침 후에도 기록과 자리를 복구합니다. 연습모드도 서버 연결이 필요하며 다른 사람은 연습 방에 입장할 수 없습니다.

상단 **♪ 버튼**으로 배경음악과 효과음을 함께 켜거나 끕니다. 기본값은 켜짐입니다. 브라우저의 자동재생 제한 때문에 첫 클릭이나 터치 뒤 음악이 들릴 수 있습니다. 배경음악은 104 BPM의 드럼·베이스·가벼운 멜로디를 Web Audio로 합성한 오리지널 루프이며 다운로드할 음원은 없습니다. 탭이 보이지 않으면 오디오를 일시정지하고 돌아오면 재생합니다. 오디오는 하나의 엔진에서 재사용하며 소리를 여러 번 켜도 음악이 중복 재생되지 않습니다.

## 모듈

| 경로 | 책임 |
| --- | --- |
| backend/Domain | 순수 게임 규칙, 원형 배치, 자동 조준, 점프 판정 |
| backend/Application | 방별 동시 실행 제어, 세션, 타이머, 스냅샷 |
| backend/Transport | SignalR Hub의 명령 진입점 |
| frontend/src/platform | SignalR 재연결, 서버 시각 추정 |
| frontend/src/platform/audio.ts | 배경음악 스케줄링, 합성 악기, 효과음, 음소거 |
| frontend/src/games/frog-jump | Canvas 연못, 개구리, 조준과 점프 애니메이션 |
| frontend/src/main.ts | 로비 및 UI 조립, 단일 버튼 입력 |
| frontend/src/contracts.ts | 서버 DTO에 대응하는 TypeScript 타입 |
| tests/FrogGame.Tests | 서버 규칙 테스트 |
| frontend/tests | 실제 브라우저 및 SignalR 통합 테스트 |

## 검증

```powershell
dotnet test PondParty.slnx
cd frontend
npm run build
npm run test:e2e
```

브라우저 테스트는 Microsoft Edge 헤드리스 모드를 사용합니다. Edge가 없는 환경에서는 설치된 Playwright Chromium에 맞춰 playwright.config.ts의 channel 설정을 변경하고 브라우저를 설치하세요. 테스트는 전용 5272/5273 포트에서 최신 서버를 자동으로 실행하여 이미 실행 중인 게임에 영향을 주지 않습니다.

서버 테스트는 2~8명 각각의 도달 가능성, 빈자리 보존, 물/충돌 판정, 중복 점프, 잘못된 턴/시각, 제한 시간 유예, 준비 조건, 세션 비밀 미노출을 검증합니다. 통합 테스트는 두 브라우저의 경기 진행, 키보드 입력, 새로고침 복구, 모바일 레이아웃, 성공 후 자리 교체, 방 격리를 검증합니다.

연습모드의 반복 진행과 종료·복구·방 격리도 검증합니다. 오디오는 브라우저에서 실제 출력 신호가 생성되는지, 끌 때 중단되고 다시 켤 때 엔진이 중복 생성되지 않는지 확인합니다.

## 배포용 빌드

프론트엔드를 먼저 빌드하면 .NET 게시 결과의 wwwroot에 자동 포함됩니다.

```powershell
cd frontend
npm ci
npm run build
cd ..
dotnet publish backend -c Release -o artifacts/server
dotnet artifacts/server/FrogGame.dll --contentRoot artifacts/server --urls http://127.0.0.1:5072
```

이 경우 http://127.0.0.1:5072 에서 웹 화면과 SignalR를 함께 제공합니다. 외부 배포 시에는 HTTPS와 WebSocket 프록시 설정을 적용하세요. 폰트만 Google Fonts에서 로드하며 접속할 수 없으면 시스템 폰트로 대체됩니다. 게임 그래픽은 외부 에셋 없이 Canvas로 그립니다.

## 현재 구현 범위

첫 실행 가능한 버전입니다. 서버 상태는 메모리에 있어 서버 재시작 시 방과 경기 기록이 사라집니다. 여러 서버 간 상태 공유, 계정, 영구 랭킹, 경기 중 신규 관전, 강퇴는 포함하지 않았습니다. 경기 중 이탈자는 자리를 유지하고 시간 초과 처리합니다. 자발적 나가기는 대기/결과 화면에서 가능합니다. 끊긴 참가자가 복귀하지 않으면 준비 조건 때문에 재시작할 수 없으므로 새 방을 만들 수 있습니다.

방별 SemaphoreSlim으로 상태를 직렬 변경하고, 상태가 바뀔 때 전체 스냅샷을 보냅니다. 작은 방에 적합한 초기 구조이며 별도 송신 큐나 분산 액터 구조는 구현하지 않았습니다. 클라이언트 타입은 현재 수동 관리합니다. 계약 세부 사항은 [SignalR 통신 계약](../integrations/signalr-protocol.md)을 참고하세요.

시각 보정은 최대 350ms 과거 입력을 허용하는 캐주얼 게임 정책입니다. 서버가 방향과 결과를 계산하지만 변조된 클릭 시각이나 자동 입력을 완전히 막는 경쟁 게임용 부정행위 방지는 아닙니다.
